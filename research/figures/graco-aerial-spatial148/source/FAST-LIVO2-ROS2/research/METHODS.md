# MegaLoc + MapClosures implementation

The current S3E configuration combines two independently queried retrieval branches. MegaLoc can propose an image match without passing a LiDAR retrieval threshold. MapClosures can propose a LiDAR match without passing MegaLoc's visual threshold. Their selected candidate union receives native MapClosures pose initialization and common GICP acceptance. This integration is an adaptation, not a claim that either paper published this combined pipeline.

MapClosures: Gupta, Guadagnino, Mersch, Vizzo and Stachniss, “Effectively Detecting Loop Closures using Point Cloud Density Maps,” ICRA 2024. [Official repository and paper link](https://github.com/PRBonn/MapClosures). This implementation pins development revision `1710f15db000a579324e3ba045cd64a0b4d706da` (CMake version 2.1.0), under the MIT license. It does not use the repository's separate `ICRA2024` tag, and does not claim exact reproduction of that paper's results. MapClosures requires no pretrained model, training or CUDA.

The C++ adapter links the pinned upstream library. It calls upstream ground alignment, density-map generation and `RansacAlignment2D`, and uses the upstream HBST implementation. Feature extraction follows `MapClosures.cpp`: ORB with 500 maximum features, one pyramid level, scale factor 1, 31-pixel patch/edge threshold, FAST threshold 35, and a second-nearest self-match Hamming distance greater than 35. Absolute density pixel coordinates and ground transforms are preserved in the serialized packet.

Native retrieval settings are the upstream defaults: 0.5 m density resolution, 0.05 density threshold, Hamming distance threshold 50 and more than five RANSAC inliers. Upstream 2D RANSAC retains a three-pixel inlier distance, two-point samples, assumed 0.1 inlier ratio and 0.999 success probability (688 trials). The native pose maps reference/candidate points into query coordinates, including both ground-alignment transforms. It seeds small_gicp GICP directly; no coarse ICP or FPFH initializer is used in this setup.

Explicit adaptations for the existing distributed pipeline:

- Input maps are the frozen five-second trailing FAST-LIVO2 submaps, expressed in each keyframe's body frame and cropped to 80 m. Their upstream keyframe stage retains one representative per 0.25 m voxel. No additional density-stage voxelization is applied. This differs from the upstream CLI's KISS-ICP voxel maps and approximately 100 m map-origin travel trigger. Keyframes remain at 1 m, 10° or two seconds, and each submap ends at its keyframe timestamp.
- Describe, insert, query and two-map matching are exposed separately by a pybind11 adapter. The public upstream API combines description, database insertion and matching, which cannot directly express a remote descriptor query. Each worker inserts only its own observed descriptor packets. Query results are restricted to causal eligible local IDs. Same-robot exclusion is 30 seconds, replacing upstream's fixed three-map skip.
- HBST uses `SplitEven` and native binary matching. At most 20 matched map IDs per receiving worker/query are shortlisted by raw binary match count before native RANSAC. Upstream instead validates every matched eligible map. The bound prevents an unbounded geometry sweep over the database; it may reduce retrieval recall.
- MegaLoc independently retrieves top-20 visual candidates per receiving worker with cosine similarity at least 0.50. MapClosures candidates require the native inlier threshold but have no visual gate. Each requester combines the three replies and selects at most one proposal per branch, using visual cosine for MegaLoc and native inlier count for MapClosures. There is a two-second cooldown per destination and branch. A pair selected by both branches is requested and verified once.
- Combined display/evaluation ranking uses the maximum of visual cosine and `native_inliers / (native_inliers + 5)`. This is an explicit rank-fusion heuristic, not a calibrated probability. Branch selection never compares those heterogeneous scores: each branch has its own raw-score budget.
- The database-derived native pose is retained for independently retrieved LiDAR candidates. A visual-only candidate obtains a pose by matching the two serialized native feature packets through a temporary native HBST index. Lack of sufficient native pose evidence is recorded as `mapclosures_no_pose`.
- The build copies upstream source and applies two small changes there: seed one `std::mt19937(0)` per RANSAC call for deterministic sampling, and return zero density for a constant counting grid to avoid division by zero. The original checkout remains unmodified. Adapter guards handle fewer than two ORB features, invalid packet sizes, nonfinite poses and improper rotations. Native RANSAC thresholds and iteration count are unchanged.

Source dependencies are pinned in `assets.lock.json`: HBST `6b0ce9f91da6e503b98aa45b22b3e2754f26c83d` (BSD-3-Clause) and Sophus `d0b7315a0d90fc6143defa54596a3a95d9fa10ec`, tag 1.24.6 (MIT). System Eigen 3.4.0, OpenCV 4.5.4 and pybind11 2.9.1 are used on this machine. The adapter source hash and installed extension SHA256 are included in stage identities; descriptor reuse checks the extension hash. Upstream and dependency notices are retained with the adapter.

MegaLoc: Berton and Masone, “MegaLoc: One Retrieval to Place Them All,” CVPR Workshops 2025, [paper](https://arxiv.org/abs/2502.17237), [source](https://github.com/gmberton/MegaLoc). Repository revision `5fe0dd697c4a70ba3e23607f6716ab3c606b16db`, MIT. Checkpoint SHA256 `d4f9f2bcb60018f91eb6a8e061ed054fd55654e10c2569cf13841ea986ffb4f8`. RGB images receive ImageNet normalization followed by antialiased 322×322 resize. The normalized 8,448-dimensional vector is serialized as float32. GPU inference is reused from frozen artifacts in this experiment.

Geometry requests contain at most 16,000 points sampled at at least 0.5 m spacing. GICP uses up to 20,000 points with a 0.4 m minimum voxel spacing and 1.5 m correspondence radius. Acceptance requires convergence, at least 100 inliers, 30% symmetric overlap within 0.6 m, RMSE at most 0.35 m and full six-axis observability. Conservative covariance floors are 2° and 0.2 m. Filter marginal covariances are diagnostic only. The constraint convention is `T_i_j = inverse(T_world_i) @ T_world_j`, candidate j to query i, with right-tangent order `[rx, ry, rz, tx, ty, tz]`.

Robot workers exchange serialized visual vectors and local density features; full clouds are sent only for selected candidates. The scheduler routes messages and counts exact wire bytes. Linux Landlock prevents workers from reading other robot stores or ground truth. Accepted constraints and rejection records retain their independently qualified retrieval sources and the native pose. Source attribution describes this run; it does not measure counterfactual performance with a branch disabled.

GTSAM 4.2 GNC-TLS uses explicit odometry noise, mutually supported inter-robot alignment and independent anchors for disconnected components. Selected GNC inliers are refitted; anchors are rebuilt if a bridge is rejected. Residuals and robust weights are exported. Evaluation alone reads ground truth: S3E orientations are placeholders, so retrieval labels use 10 m position proximity and trajectory error is position-only. Each connected component uses one shared rigid alignment without scale fitting. GNSS antenna lever arms are uncorrected. Exact 6-DoF checks use synthetic known transforms.
